# ESP 虚拟键盘 · 固件包与构建说明

> 适用设备：ESP32-C3 BLE 虚拟键盘（USB 直连）
> 固件版本：**20261009**（2026-10-09）
> 定位：**ESPEZUpdater 通用固件升级工具**的项目侧接入目录（内置构建套件 + 配置档 + 构建产物）。
> 目录：`firmware-updater/`

---

## 一、这是什么

本目录是 ESP 虚拟键盘按 ESPEZUpdater《构建套件与项目集成机制》产出的**项目侧集成目录**：

- **内置构建套件** `build-kit\`：独立于运行时工具，在**本项目内**构建固件包；
- **两份配置档**：`build.json`（如何构建）+ `profile.json`（页面可编辑字段与协议映射）；
- **构建产物** `dist\`：空凭据固件包（**不含任何真实 WiFi 凭据**），可安全分发；
- 运行时工具（网页烧录 + 串口配网）由独立的 **ESPEZUpdater** 提供，本目录**不内置运行时副本**。

> 旧的专用工具（`build_package.cmd` / `gen_manifest.ps1` / 自带前端 / `esptool.exe` / `server.ps1`）
> 已废弃并移除；其历史可从 git 记录找回。

## 二、目录结构

```text
firmware-updater/
├─ 使用说明.md                    # 本文档
├─ build-kit/                     # 内置构建套件（复制自 ESPEZUpdater\build-kit\，升级时整目录覆盖）
│  ├─ build_common.ps1            #  通用构建驱动
│  ├─ empty_creds.ps1             #  L1 空凭据改写
│  ├─ templates/                  #  配置档模板
│  └─ README.md                   #  套件用法
├─ build.json                     # 项目构建档（profileSource: "profile.json"）
├─ profile.json                   # 项目 UI 档（中英双语 + protocol 映射）
└─ dist/                          # ★构建产物（由 build-kit 生成，勿手工编辑）
   ├─ firmware/
   │  ├─ default/                 # 单固件（标准固件）
   │  │  ├─ bootloader.bin / partitions.bin / boot_app0.bin / app.bin
   │  │  ├─ manifest.json         # 版本 / 芯片 / credentials:"empty" / flash / 每文件 SHA256
   │  │  ├─ profile.json          # 随包（= 根 profile.json 副本）
   │  │  └─ VERSION.txt
   │  ├─ profile.json             # 页面引导用（加载 manifest 前发现变体）
   │  └─ verify.log               # 空凭据校验留痕（命中 0 / PASS）
   ├─ build_tmp/                  # 中间副本（本地，不入库）
   └─ 固件包_v<版本>.zip           # ★仅固件包（内含 firmware/ 全量，本地生成，不入库）
```

**为什么要带 `profile.json`**：ESPEZUpdater 是通用工具，不含项目专有字段；运行时读取固件包内的
`profile.json` 动态渲染页面。

## 三、构建（维护者）

在**本目录**执行：

```powershell
# 仅固件包（默认）：产出 dist\firmware\... + dist\固件包_v<版本>.zip
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-kit\build_common.ps1 -Build .\build.json
```

- 升级源码后，先在 `F:\ESPVirtualKeyboard\config.h` 更新 `FW_VERSION`（日期式，如 `"20261009"`）；
- 构建流程：清副本 → 拷源码 → 变体宏 → L1 清空凭据 → 编译 → 抽四件套 → 体积检查 →
  L2/L3 校验 → 写 `manifest.json`/`profile.json`/`VERSION.txt` → 打包 zip → 写 `verify.log`；
- **工作区源码（含 `config.h`）零改动**（仅操作 `dist\build_tmp\` 副本）；
- 任一层校验失败即中止（fail-closed），不产出可分发产物；
- 可选参数：`-OutDir <目录>`（默认 `.\dist`）、`-SkipZip`、`-KeepTmp`；
- 本目录**不启用** `-Bundle`（自包含分发交给独立 ESPEZUpdater）。

> 套件升级：用工具仓的 `build-kit\` **整目录覆盖**本项目 `build-kit\` 即可，杜绝代码漂移。

## 四、配合 ESPEZUpdater 使用

> 需 ESPEZUpdater **v20261009 及以上**（本 `profile.json` 为 schema 2；工具版本见其 `version.json`）。

**方式一：直接导入固件包（推荐）**

1. 取 ESPEZUpdater 运行时工具并双击 `一键升级.bat`（或 `upgrade.bat`），浏览器打开其本地地址（默认 `http://127.0.0.1:8123`，端口冲突自动顺延）；
2. 在页面点「**选择固件目录…**」选择本项目 `dist\firmware\`，或直接把 `dist\固件包_v<版本>.zip` **拖入页面**导入
   （严格模式要求包内同时含 `manifest.json` + `profile.json`，本项目包已满足）；
3. 页面按 `profile.json` 渲染：变体「标准固件」、字段「WiFi 名称 / 密码」、
   开关「写入 / 覆盖 / 烧录前全擦除」（「更新」开关对本固件不适用，已隐藏；**「烧录前全擦除」默认不勾选**，
   升级保留设备已保存配置，需要全新刷写时手动勾选）；中英双语可切换；
4. 填写 WiFi（**可留空 = 不修改**）→「连接设备」→「开始升级」；刷写完成后工具**自动经 USB 串口写入配置**并等待连接；
5. 收到「配网成功」即可关闭页面、拔线。

**方式二：替换工具内置固件目录**

把本项目 `dist\firmware\` 放到工具目录的 `firmware\`（覆盖其内置演示固件），再按方式一第 1、3–5 步操作。

> 无硬件自测：地址后加 `?mock=1`（如 `http://127.0.0.1:8123/?mock=1`）可走通「连接 → 烧录（模拟）→ 写入配置」全流程。
> 命令行兜底：工具目录的 `flash_cli.bat`（仅烧录，不含配网）。

## 五、空凭据与安全

- `dist\firmware\` 与 zip 均为**空凭据**：不含 WiFi 名称/密码，**可安全公开分发**；
- 构建经三层强制校验，任一层失败即中止（fail-closed）：
  - **L1 源层**：副本 `config.h` 的 `WIFI_SSID` / `WIFI_PASSWORD` 强制清空（工作区源码不动）；
  - **L2 源码层**：独立断言副本凭据全空 + 扫描副本源码敏感特征/内网 IP；
  - **L3 产物层**：对 4 个 bin 做字节级扫描（ASCII + UTF-16LE）。
- 校验留痕见 `dist\firmware\verify.log`（命中数 = 0，result: PASS）；
- 真实凭据在刷机时由使用者输入，经 **USB 串口**写入设备 **NVS**（明文，与业界常规一致）；
- 仓库 `config.h` 保留开发者凭据用于 IDE 直接编译；分发包才为空凭据；
- 注意：`WEB_AUTH_USERNAME` / `WEB_AUTH_PASSWORD`（Web 面板登录）为项目功能默认值，**不在清空范围内**。

## 六、配置档说明

### 6.1 `build.json`（构建档）

| 字段 | 值/说明 |
|---|---|
| `sketchDir` | `F:\ESPVirtualKeyboard`（**只读**，构建不改动） |
| `sketchName` | `ESPVirtualKeyboard` |
| `variants` | 单变体 `default` |
| `versionMacro` | `FW_VERSION`（当前 `"20261009"`） |
| `credentialMacros` | `WIFI_SSID` / `WIFI_PASSWORD` |
| `genericNeedles` | 空（项目无私钥/真实域名） |
| `allowValues` | 固件中合法存在、不视为泄露的值（`Debug` / `12345678` / 回环与默认网络串） |
| `fqbn` | `esp32:esp32:esp32c3:...CDCOnBoot=cdc...FlashMode=dio...huge_app`（与 IDE 菜单一致） |
| `flash` | `dio / 80m / 4MB` |
| `profileSource` | `profile.json`（相对 `build.json`） |

### 6.2 `profile.json`（UI 档，schema 2）

- 双语（`zh` / `en`）、单变体、单分组（网络）；
- 字段：`ssid`（maxlength 32）、`pass`（password，敏感掩码，maxlength 63）；
- `protocol` 映射：本固件使用 `wifi` / `wifi_saved` / `wifi_clear`，与工具正典名的差异在此适配；
- `actions`（schema 2）：**开始升级** / **写入配置**（`gate:write`，`waitFor:wifi_saved`，成功后跟随等待 `wifi_connected`/`wifi_failed`/`error`）/ **清除配网信息**（`wifi_clear`）；
- `statusView`（schema 2）：把设备扁平 `status` 渲染为中文摘要（内置凭据 / NVS 凭据 / 覆盖 / 网络 / IP）；
- 敏感字段标 `sensitive:true`（仅用于 UI 掩码，**不含真值**）；
- schema 门禁：工具 `version.json.profileSchema < 2` 时会拒绝加载本档（请升级工具）。

## 七、协议与固件要求

- 固件须实现串口配网协议（`@` 前缀单行 JSON、115200、非阻塞、行长上限 256B）：
  `ping` / `status` / `wifi{ssid,pass,override}` / `wifi_clear`，事件
  `pong{proto:1,fw}` / `wifi_saved` / `wifi_connecting` / `wifi_connected{ip}` / `wifi_failed{status}` / `status` / `error`；
- 凭据优先级：NVS 覆盖位 > 编译期非空 > NVS > 空（进入配网等待）；
- `ENABLE_SERIAL_PROVISION` 可整体关闭配网协议（关闭后无 `@` 应答，仅普通日志）。
